# /session-record

Activate full session recording for the current conversation. Every user message and Claude response is appended verbatim to a session file, with visual formatting for readability.

**This is a mode, not a one-shot action.** Once activated, recording continues for the entire session until the user says "stop recording" or the session ends.

---

## On Activation

1. **Determine session file path.** Check if `_project/sessions/` exists in the current project. If yes, use it. If not, create it.

2. **Generate filename**: `_project/sessions/YYYY-MM-DD-{LETTER}.md` where `{LETTER}` is the next unused uppercase letter for today's date (A, B, C...). Check existing files to avoid collision.

3. **Ask the user** (via AskUserQuestion, one question only):
   - "What is the topic of this session?" — free text, used as the session title.

4. **Create the session file** with this header:

```markdown
# Session {LETTER} — {topic}

- **Date**: YYYY-MM-DD
- **Type**: {inferred from topic — e.g., "Design Discussion", "Implementation", "Debugging"}
- **Participants**: {user name from memory or "User"} + Claude
- **Format**: Full dialogue recording

> **How to continue this discussion**: In a new Claude session, provide this file as context and pick up from the latest round.

---
```

5. **Confirm to user**: "Recording started. File: `_project/sessions/{filename}`"

6. **Retroactive capture**: If there were prior exchanges in this conversation before `/session-record` was invoked, reconstruct and record them as Round 1, 2, etc.

---

## Recording Protocol — Every Exchange

After EVERY user message + Claude response pair, append to the session file:

### Format

```markdown
## {COLOR} Round {N}: {short title}

> #### 💬 {UserName}
>
> {user's message — verbatim, preserve original formatting}

#### 🔮 Claude

{Claude's response — verbatim, preserve original formatting}

---
```

### Round Color Rotation

Cycle through these colors for visual distinction:
- Round 1: 🔵
- Round 2: 🟠
- Round 3: 🟢
- Round 4: 🟣
- Round 5: 🔴
- Round 6: 🟡
- Round 7+: cycle back to 🔵

### Rules

- **Verbatim**: Record the actual words said, not a summary. The whole point is lossless capture.
- **Short title**: 3-8 words summarizing the round's topic, generated by Claude.
- **User name**: Use the name from auto-memory if available; otherwise use "User".
- **Append, don't rewrite**: Always use Edit tool to append to the file. Never rewrite the entire file after Round 1.
- **Tables, code, diagrams**: Preserve all formatting from the original exchange.
- **Claude actions**: When Claude performs tool calls (file reads, edits, searches), note them briefly in italics: *（read file X, edited Y）* — don't dump full tool outputs.

---

## Status Footer

Keep a running status section at the bottom of the file. Update it each round by replacing the previous version:

```markdown
## ⚪ Current Status

- **Rounds recorded**: {N}
- **Key decisions made**: {bullet list}
- **Open questions**: {bullet list}
- **Suggested next topic**: {what Claude thinks should be discussed next}
```

---

## On Session End

When the user says "stop recording", ends the session, or triggers session-end protocol:

1. Finalize the status footer.
2. Output: "Session recorded: {N} rounds in `{filepath}`"

---

## Edge Cases

- **Long messages**: Record in full. Don't truncate. The user explicitly chose full recording.
- **Multiple rapid exchanges**: Each user→Claude pair is one round, regardless of length.
- **User edits/corrections**: If the user corrects something, record the correction as a new round, not by editing the old one.
- **File gets very large**: That's expected and fine. Append only, never trim.
