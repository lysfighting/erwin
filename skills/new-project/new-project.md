# /new-project

Scaffold a new project with the complete AI-assisted project intelligence infrastructure,
derived from the erwin project pattern.

**Run from the project root directory before starting work.**

---

## What Gets Created

**In the project directory (committed to git):**
```
_project/
├── GOALS.md           ← Vision + OKRs template
├── CURRENT.md         ← Living status (read before any implementation)
├── ROADMAP.md         ← Milestone plan template
├── ideas/
│   ├── README.md      ← Idea garden rules (4 stages: Seed→Sprout→Plant→Fruit)
│   └── INBOX.md       ← Raw idea captures, processed weekly
├── decisions/
│   └── README.md      ← ADR template + index
├── sessions/
│   └── README.md      ← Session log template
├── issues/
│   └── README.md      ← Issue tracking template
└── releases/
    └── README.md      ← Narrative release notes template
CLAUDE.md              ← AI navigation handbook (loaded every conversation)
CHANGELOG.md           ← Keep a Changelog format
.claude/
└── rules/
    ├── ai-workflow.md     ← Session protocol (principle-based CURRENT.md trigger)
    └── git-conventions.md ← Commit message format
```

**Locally on this machine (NOT in git — Claude's cognition layer):**
```
~/.claude/projects/{hash}/memory/MEMORY.md
```

## Steps

### Step 1: Gather Project Metadata

Use `AskUserQuestion` with these 4 questions:

```
Q1: "What is this project?" (header: "Project name")
  Options: suggest 3-4 common patterns but allow custom
  [user types the project name — kebab-case slug]

Q2: "One-line description?" (header: "Description")
  Options: "I'll type it" / show 3 example formats

Q3: "Tech stack?" (header: "Tech stack")
  Options:
    - "React/TypeScript/Vite"
    - "Python + FastAPI"
    - "Node.js/TypeScript"
    - "Other (I'll describe)"

Q4: "Primary language for AI responses?" (header: "AI language")
  Options:
    - "Chinese (中文)"
    - "English"
    - "Mixed (Chinese discussion, English code)"
```

Store answers as: `{project-name}`, `{description}`, `{tech-stack}`, `{ai-language}`.

### Step 2: Safety Check

```bash
# Check if files already exist
[ -f CLAUDE.md ] && echo "WARNING: CLAUDE.md exists"
[ -d _project ] && echo "WARNING: _project/ exists"
```

If either exists, use `AskUserQuestion`:
- "CLAUDE.md / _project/ already exists. Overwrite?" → Yes (fresh init) / No (abort) / Merge (add missing files only)

### Step 3: Create Directories

```bash
mkdir -p _project/ideas/skills _project/ideas/meta
mkdir -p _project/decisions _project/sessions _project/issues _project/releases
mkdir -p .claude/rules
```

### Step 4: Write All Files

Use the `Write` tool for each file. Substitute `{project-name}`, `{description}`, `{tech-stack}` with actual values from Step 1. Use today's date for `{date}`.

**Write in this order:**
1. All `_project/` README files (independent)
2. `_project/GOALS.md`, `_project/CURRENT.md`, `_project/ROADMAP.md`
3. `CLAUDE.md`
4. `.claude/rules/ai-workflow.md` and `.claude/rules/git-conventions.md`
5. `CHANGELOG.md`

Templates for each file are below.

### Step 5: Initialize Auto-Memory

```bash
# Compute Claude Code's project hash (path → hash)
PROJ_HASH=$(pwd | tr '/' '-')
mkdir -p ~/.claude/projects/$PROJ_HASH/memory/
```

Write `~/.claude/projects/$PROJ_HASH/memory/MEMORY.md` using the MEMORY.md template below.

### Step 6: Git Init + First Commit

```bash
# Init git if not already a repo
git rev-parse --git-dir 2>/dev/null || git init

# Stage project intelligence files
git add _project/ CLAUDE.md CHANGELOG.md .claude/

# First commit
git commit -m "chore: init project intelligence layer

Bootstrap _project/ structure, CLAUDE.md, .claude/rules/, CHANGELOG.md.
Generated by /new-project skill (erwin project pattern v0.5.0)."
```

### Step 7: Report to User

Output:
```
✅ Project initialized: {project-name}

Created:
  _project/          (GOALS, CURRENT, ROADMAP, ideas, decisions, sessions, issues, releases)
  CLAUDE.md          (AI navigation handbook)
  .claude/rules/     (ai-workflow.md, git-conventions.md)
  CHANGELOG.md       (Keep a Changelog format)
  ~/.claude/projects/{hash}/memory/MEMORY.md  (Claude's auto-memory)

First commit: done ✓

Next steps:
  1. Fill in _project/GOALS.md — your vision and OKRs
  2. Fill in _project/CURRENT.md — your current task
  3. Start working — Claude will read CLAUDE.md + CURRENT.md at the start of each session
```

### .claude/rules/ai-workflow.md

```markdown
---
# AI session workflow rules
---

# AI Session Workflow Protocol

## 何时读 CURRENT.md — 原则优先，不罗列场景

**一个判断测试**：「我现在的行动，如果方向错了，需要撤销多少工作？」

- **撤销成本高** → 先读 `_project/CURRENT.md`（30秒），再行动
- **撤销成本低** → 直接做，无需读

**必须先读**（行动产出不可逆结果）：
- 即将写代码、创建或修改文件
- 即将做架构或技术决策
- 用户说「继续」「下一步」「做吧」「drive」
- 对话开始后第一次实质性行动

**无需读**（纯对话，不留痕迹）：
- 解释概念、回答技术问题
- 讨论方案但尚未决定动手

> 核心逻辑来自 drive-skill 的 Cardinal Rule：永不停止，除非检测到方向偏差。
> 读 CURRENT.md 是在行动前排除「方向偏差」的最小成本手段。

## 同步读取（与 CURRENT.md 一起）

当读 CURRENT.md 时，同步读：
- `_project/GOALS.md` — 验证与北极星对齐
- 相关 ADR — 如果即将改动某个有决策记录的组件

## During Session

- Discovered bugs/tasks → create `_project/issues/ISS-NNNN-title.md`
- Major decisions → create `_project/decisions/NNNN-title.md`
- Good skill ideas → add to `_project/ideas/INBOX.md` immediately

## Session End (mandatory)

1. Update `_project/CURRENT.md`
2. Write `_project/sessions/YYYY-MM-DD.md`
3. Update `CHANGELOG.md` if features completed
4. Update `~/.claude/projects/{project-hash}/memory/MEMORY.md`
   — 新发现的规律、用户偏好、技术陷阱、项目特有知识
5. Run: `git add -A && git commit -m "type(scope): description"`

## File Size Limits

| File | Target | Max |
|------|--------|-----|
| CLAUDE.md | <150 lines | 200 lines |
| _project/CURRENT.md | <80 lines | 120 lines |
| ADR files | 50-100 lines | 150 lines |
| Session logs | 50-150 lines | 300 lines |

## What Not To Do

- Don't skip CURRENT.md before irreversible actions — stale context = direction error
- Don't skip the session-end update — stale CURRENT.md = broken continuity
- Don't add large images or binary files to docs/ or _project/
```
