# Wing Tips Pool
# One tip per line. Skills randomly pick one to display after output.
# Lines starting with # are comments and should be skipped.
/wing auto #N — 一键完成 claim→drive→ship，适合小任务快速交付
/wing wrap — 已经写完代码了？用 wrap 反向补齐 issue + PR 流程
/wing doctor — 检查本地 branch 健康状态，发现孤儿分支、过期 stash 等问题
/wing doctor fix — 自动修复 doctor 发现的问题（清理孤儿分支、修复标签等）
/wing-issue fix #N — 把已有的 GitHub Issue 纳入 wing 管理
/wing-issue batch V0.2 -- ... — 批量创建 milestone + 多个 Issue
/wing-ship review — 让 AI 对当前 PR 做代码审查（安全/架构/质量）
/wing-ship sync — 在 base branch 上 rebase，保持分支最新
/wing-issue update #N — AI 辅助编辑已有 Issue 内容
/wing-issue #N <文字> — 快速给 Issue 添加评论，不用打开浏览器
/wing queue — 按优先级查看所有待办 mission，找到下一个要做的事
/wing #42 — 快速查看任意 mission 的详情（branch、PR、进度）
/wing config — 查看和编辑 wing 配置（测试命令、通知、quality gates）
worktree 模式：git config --local wing.worktree true — 每个 mission 独立目录，并行开发不冲突
/wing-rc promote — 将 staging 验证通过的 RC 发布到 production（squash merge + tag + Release）
/wing-rc fix — 在 RC 上 cherry-pick 修复，不用重新切 RC 分支
/wing-rc hotfix — 线上紧急修复：在 main 上修 → tag → 自动回溯到 develop
/wing-rc cancel — 取消当前 RC，清理远程分支，回到开发状态
/wing sync — 独立 rebase 当前分支到 base branch 最新，不走 ship 流程
/wing share #N — 把 mission 上下文分享给其他 MC，跨 MC 协作不丢信息
/wing-claim list — 查看你被 assign 的所有 mission，选一个开始
/wing-ship done — mission 结束后一键清理：删分支、关 worktree、更新标签
配置 quality gates：在 config.yml 的 conventions.required_checks 里加 CI job 名称
/wing-issue #N — 不带文字 = 查看详情，带文字 = 添加评论，两种用法
配置通知：config.yml 的 notifications 区域支持 Slack、飞书、webhook
monorepo 项目可以在 config.yml 配置 project.services — 每个 service 独立测试
/wing help — 所有命令速查表，10 秒内找到你要的功能
