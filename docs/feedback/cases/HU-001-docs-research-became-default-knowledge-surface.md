# HU-001 — `docs/research/` became the default durable knowledge surface

- `case_id`: `HU-001`
- `date`: `2026-04-02`
- `title`: `docs/research became the default durable knowledge surface`
- `kind`: `coordination failure`
- `scope`: `docs`
- `symptom`: durable knowledge, proposal-adjacent notes, and one-off research were mixed together, so fresh sessions had to rediscover canonical state by rereading large research piles
- `what_happened`: before the knowledge-system refactor, the repo kept accumulating active thinking inside `docs/research/`, even when the material had become cross-cutting knowledge or proposal input rather than one-time incubation analysis
- `where_seen`: `docs/research/` before the 2026-04-02 refactor, `_project/archive/sessions/2026-04-02-B.md`, `docs/research/README.md`
- `trigger`: new notes kept landing in the broadest available directory because there was no narrower active knowledge boundary
- `why_current_system_allowed_it`: the repo had no explicit `feedback -> knowledge -> proposals` model, no canonical knowledge layer, and no durable rule that `docs/research/` was an incubation boundary rather than the default sink
- `layer_that_should_have_caught_it`: `knowledge`, `docs`, `automation`
- `evidence`: `docs/knowledge/operating-model.md`, `_project/archive/sessions/2026-04-02-B.md`, `docs/research/README.md`
- `repeatability`: `confirmed-repeat`
- `impact`: canonical state became harder to find, durable insight looked provisional, and new sessions risked treating historical audits as if they were the live knowledge base
- `recommended_next_step`: `distill into knowledge`
- `linked_knowledge`: `docs/knowledge/active-threads.md`, `docs/knowledge/operating-model.md`
- `linked_proposals`: `docs/proposals/harness-proposal-ledger.md`
- `status`: `distilled-into-knowledge`
