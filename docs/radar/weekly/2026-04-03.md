## Theme Deep Dive

The week's strongest shared theme is that agent systems are hardening around operational surfaces rather than around one more model card. Anthropic widened output budgets, narrowed migration paths, and spent public airtime showing how Claude Code should be used in real engineering organizations. Google shipped agent framework versions that look more like runtime platforms than helper libraries, then explicitly taught developers to externalize expertise as skills instead of stuffing everything into a monolithic prompt. OpenAI, meanwhile, made the budget and access boundary around Codex more visible.

That combination matters because it reframes what "agent progress" means. The center of gravity is shifting from pure capability claims toward governed execution: how much work the agent can do in one run, how operators approve or inspect that work, how runtime knowledge is loaded, and how enterprises meter the resulting spend. Anthropic is especially important here because its official surfaces this week showed a full-stack pattern. Engineering and Claude Blog were comparatively quiet after [Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps) on **March 24, 2026** and [Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode) on **March 25, 2026**, but the platform docs and webinar/event surfaces kept pushing the same underlying story: long-running coding agents need larger execution budgets, migration discipline, approval design, and operator training.

The durable read is that "harness" is no longer just our interpretation layer. Vendors are converging on runtime topology, policy gates, skills or externalized instruction loading, and traceable execution as the real product surface for agentic systems.

## Harness Evolution Proposals

### Title

Trace-first delegated execution review

### Source

Google [ADK Go 1.0 Arrives!](https://developers.googleblog.com/en/adk-go-10-arrives/) on **March 31, 2026**; Anthropic [Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode) on **March 25, 2026**; Anthropic [Claude Code for Semiconductor Teams](https://www.anthropic.com/webinars/claude-code-for-semiconductor-teams) on **March 31, 2026**

### Observed Pattern

Production agent systems are being presented with traceability, approval context, and post-hoc inspection as default operating surfaces rather than optional debugging extras.

### Why It Matters For Harness

Harness already models delegated work, councils, and follow-up packets, but it does not yet treat execution traces as a first-class review object attached to those control-plane artifacts.

### Recommended Disposition

`encode-as-eval`

### What We Would Change If Adopted

Add an evaluation path that replays delegated-run state with trace checkpoints, approval decisions, and artifact lineage so we can judge whether a run stayed legible under multi-step pressure.

### Why We Should Not Cargo-Cult This

We should not copy any vendor's tracing schema or assume that more telemetry automatically improves governance. The important move is legible execution review, not maximal logging.

### Title

Policy-mediated autonomy tiers

### Source

Anthropic [Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode) on **March 25, 2026**; Google [Announcing ADK for Java 1.0.0: Building the Future of AI Agents in Java](https://developers.googleblog.com/en/announcing-adk-for-java-100-building-the-future-of-ai-agents-in-java/) on **March 30, 2026**; Google [ADK Go 1.0 Arrives!](https://developers.googleblog.com/en/adk-go-10-arrives/) on **March 31, 2026**

### Observed Pattern

The field is moving away from a binary choice between fully manual approval and unrestricted autonomy. Vendors are inserting classifiers, HITL checkpoints, and scoped approval flows between those extremes.

### Why It Matters For Harness

Harness already distinguishes governance and execution, but the next pressure point is whether approval rules can be expressed as runtime policy tiers rather than as ad hoc stop or go behavior.

### Recommended Disposition

`prototype`

### What We Would Change If Adopted

Prototype a narrow policy layer that lets a run declare which action classes are auto-allowed, escalated, or blocked, then test whether delegated teammate flows remain understandable when those gates are active.

### Why We Should Not Cargo-Cult This

We should not blindly insert classifier gates everywhere. If the policy layer becomes opaque, we only trade one unreadable autonomy mode for another.

### Title

Skill-loaded runtime topology

### Source

Google [Developer's Guide to Building ADK Agents with Skills](https://developers.googleblog.com/developers-guide-to-building-adk-agents-with-skills/) on **April 1, 2026**; Anthropic [Ship Code Faster with Claude Code on Vertex AI](https://www.anthropic.com/webinars/ship-code-faster-with-claude-code-on-vertex-ai) on **April 2, 2026**; Anthropic [Claude API release notes](https://platform.claude.com/docs/en/release-notes/overview#march-30-2026) on **March 30, 2026**

### Observed Pattern

Vendors are treating runtime knowledge loading, deployment topology, and long-run output budget as configurable system design surfaces rather than prompt-authoring details.

### Why It Matters For Harness

This is the clearest external validation that reusable skills plus explicit runtime shape may be more durable than bespoke one-off orchestration prompts.

### Recommended Disposition

`watch`

### What We Would Change If Adopted

Tighten the connection between Harness runtime roles and load-on-demand skills so that councils, delegated teammates, and automation lanes can expose which expertise packs they loaded and when.

### Why We Should Not Cargo-Cult This

We should not adopt framework packaging just because Google named it. The point is explicit, inspectable knowledge loading, not imitation of ADK-specific object models.
