# AI Agent Daily Radar - 2026-04-02

Coverage window: 2026-03-27 to 2026-04-02

## New Signals

1. **2026-03-31 | Google | ADK Go 1.0 turns agent services into a production surface**
   Google shipped [ADK Go 1.0 Arrives!](https://developers.googleblog.com/en/adk-go-10-arrives/), emphasizing native OpenTelemetry tracing, YAML configuration, a plugin system for self-healing logic, Agent2Agent protocol refinement, and human-in-the-loop confirmations. This is a clear shift from "agent scripts" toward governable long-running services.

2. **2026-03-30 | Google | ADK Java 1.0 adds explicit app/plugin boundaries plus stateful services**
   Google shipped [Announcing ADK for Java 1.0.0: Building the Future of AI Agents in Java](https://developers.googleblog.com/en/announcing-adk-for-java-100-building-the-future-of-ai-agents-in-java/). The strongest details are the new `App` and `Plugin` architecture, built-in HITL workflows, event compaction for context control, A2A interoperability, and session/memory services backed by Firestore and Vertex AI.

3. **2026-03-30 | Anthropic | Claude API expands long-output batch generation while tightening context-window migration**
   Anthropic's [release notes](https://platform.claude.com/docs/en/release-notes/overview#march-30-2026) raised the Message Batches API `max_tokens` cap to 300k for Claude Opus 4.6 and Sonnet 4.6 via the `output-300k-2026-03-24` beta header. The same update also set an **April 30, 2026** retirement date for the 1M-token beta on older Sonnet lines, pushing long-context usage onto the newest models.

4. **2026-03-26 | Google | Search Live global rollout shows Gemini 3.1 Flash Live as the new realtime voice-agent substrate**
   Google's [Search Live global expansion post](https://blog.google/intl/pt-pt/produtos/connect-communicate/a-pesquisa-live-expande-se-globalmente/) says the rollout is powered by Gemini 3.1 Flash Live, with multilingual realtime voice plus camera interaction across 200+ countries and territories. Even though this is a product post, it is a strong first-party signal that low-latency multimodal conversational agents are now a mainstream deployment surface.

## Candidate Proposals

1. **Trace-first delegated-run review**
   - `source_type`: first-party + secondary stress-test
   - `problem_pattern`: long-running agents are being shipped with tracing and post-hoc inspection as core runtime features, not optional add-ons
   - `why_it_matters_for_harness`: Harness already reasons about delegated work, councils, and follow-up packets, but its learning loop should test whether those control-plane objects stay legible under real multi-step execution pressure
   - `recommended_disposition`: `encode-as-eval`

2. **Policy-aware autonomy gates**
   - `source_type`: first-party
   - `problem_pattern`: vendors are replacing binary "manual vs autonomous" execution with classifier- or workflow-mediated approval gates
   - `why_it_matters_for_harness`: this is the clearest shared pattern between Anthropic auto mode and Google's HITL-centric ADK releases, and it matters more than raw autonomy marketing
   - `recommended_disposition`: `prototype`

3. **Configurable agent topology over bespoke orchestration**
   - `source_type`: first-party
   - `problem_pattern`: ADK Go YAML configs, ADK Java app/plugin boundaries, and Anthropic's harness framing all point toward explicit runtime topology as a first-class design surface
   - `why_it_matters_for_harness`: Harness should keep watching whether durable agent systems are converging on declarative topology plus runtime services, or whether this remains framework-specific packaging
   - `recommended_disposition`: `watch`
