# AI Agent Daily Radar — 2026-04-03

Window: 2026-03-27 to 2026-04-03

## New Signals

- **OpenAI moved the conversation from model access to capitalized agent infrastructure.** In [OpenAI raises $122 billion to accelerate the next phase of AI](https://openai.com/index/accelerating-the-next-phase-ai/) on **March 31, 2026**, OpenAI explicitly tied durable compute, enterprise deployment, API throughput, and Codex growth into one flywheel. The most Harness-relevant detail is not the headline financing by itself, but the claim that Codex now serves over 2 million weekly users while API traffic exceeds 15 billion tokens per minute.
- **OpenAI is productizing Codex as a separately metered enterprise surface.** OpenAI’s help article [Managing members, seat types, roles and access in ChatGPT Enterprise](https://help.openai.com/en/articles/8266401-managing-members-seat-types-roles-and-access-in-chatgpt-enterprise) was updated **April 2, 2026** to add `Codex` seats and a token-priced `Codex Rate Card` for Enterprise. That is a concrete signal that agent usage is being governed as its own budget, seat, and access-control plane rather than as a generic chat add-on.
- **Google is now bundling realtime voice and project-aware coding into one developer story.** In [The latest AI news we announced in March 2026](https://blog.google/innovation-and-ai/technology/ai/google-ai-updates-march-2026/) on **April 1, 2026**, Google highlighted `Gemini 3.1 Flash Live` plus the upgraded Google AI Studio experience with the `Google Antigravity` coding agent and `Build mode`. The important read is convergence: low-latency audio, tool access, database hookup, and project-aware code edits are now marketed as one coherent build surface.
- **Qwen is still pushing toward native omni-modal agents.** The official [Qwen](https://qwen.ai/) site currently foregrounds [Qwen3.5-Omni: Scaling Up, Toward Native Omni-Modal AGI](https://qwen.ai/). The page I checked did **not** expose a clear publish date, so I am treating this as an in-window surfaced signal rather than a date-pinned launch. Qwen positions it as a fully omnimodal model spanning text, images, audio, and audio-video, with `Plus`, `Flash`, and `Light` variants plus 256k context. The notable direction is not just multimodality, but that Qwen is framing the model as a general agent substrate rather than a separate stack of modality-specific tools.
- **DeepSeek’s official status feed stayed noisy across both web and API surfaces.** DeepSeek’s status history logged [Web/API service degraded performance](https://status.deepseek.com/incidents/lqrmk53rs6d3) on **March 31, 2026** and [Web/API service not available](https://status.deepseek.com/incidents/rjs0ljjlqhsw) on **March 30, 2026**. This is an operational signal rather than a product launch, but it matters because multi-provider agent systems still need provider health isolation, retries, and fallback paths.

## Harness-Relevant Signals

- OpenAI’s split between ChatGPT seats and Codex seats strengthens the case that agent execution should be treated as a governed runtime with explicit budgets, access scopes, and observability boundaries.
- Google’s packaging of `Flash Live` plus `Antigravity` suggests the frontier build surface is converging on one workflow where conversation, realtime I/O, tools, and project mutation are no longer separate product categories.
- Qwen’s omni-modal direction increases pressure on Harness evaluations to cover more than text and code. The near-term need is not implementation churn, but keeping eval and proposal language ready for audio/video-grounded tasks.
- DeepSeek’s service incidents are a practical reminder that runtime reliability is now part of the product surface. Provider diversity only matters if the harness can degrade gracefully when one backend goes unstable.
