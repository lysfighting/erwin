# Research Boundary

`docs/research/` is no longer the active knowledge base.

It is the incubation and one-off analysis boundary for:

- early design specs
- architectural synthesis notes
- audits
- deep dives tied to a specific investigation

Many of these files still matter.
They are not junk.
But new durable knowledge should not default to this directory.

## Use This Directory For

- historical design inputs that still explain why a system looks the way it does
- audits such as gap or drift reviews
- bounded research spikes that may later be absorbed elsewhere

## Do Not Use This Directory For

- the main radar layer
- structured Harness usage feedback
- long-lived knowledge threads
- canonical proposal ledgers

If a note becomes durable and cross-cutting, it should usually move into `docs/knowledge/` or a more specific canonical surface.
