## Theme

Harness ownership-control pass: selector-aware ownership transfer

## Summary

Moved ownership governance beyond raw string claims.

This pass keeps backward compatibility with legacy `ownership_claims`, but the runtime now normalizes them into structured selectors and can formally transfer bounded ownership between active runs in the same mission.

That closes another control-plane gap:
ownership no longer has to drift implicitly when work changes hands.

## Major outcomes

### 1. Ownership is now selector-aware

- runs, contracts, and missions now carry `ownership_selectors`
- missions also aggregate `ownership_transfers`
- overlap checks still respect the old string claims, but now operate through normalized selector identity

### 2. Formal ownership transfer exists

- added `runs transfer-ownership SOURCE_RUN_ID TARGET_RUN_ID --owns=... --reason=...`
- current transfer policy is intentionally bounded:
  - same mission only
  - active runs only
  - bounded selectors only
  - no transfer of mission/branch anchor selectors
- transfer events are durable runtime records instead of silent edits

### 3. Legacy runtime state still upgrades cleanly

- `maintenance normalize` now backfills `ownership_selectors` when only legacy `ownership_claims` exist
- real repo runtime remained healthy after the selector-aware upgrade

### 4. Smoke now guards ownership transfer

- teammate smoke now exercises a real selector transfer between two active teammate runs
- the target must gain the selector
- the source must lose it
- `doctor` must remain clean afterward
