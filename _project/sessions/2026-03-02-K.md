## What Happened

1. User feedback: "当前的 skill 不好，能不能结合 GitHub 的 Issue、PR 等体系？"
2. Reference: `../vi-agent/.claude` — a mature teamwork implementation with board.md, worktrees, PR flow

## Key Decisions

### GitHub-First Architecture (方案 D)

Evaluated 4 approaches for task source of truth:
- A: Pure GitHub (no local files) — too bare, AI loses context
- B: GitHub + persistent local Contracts — sync drift risk
- C: GitHub Issues + structured templates — 80% good but limited
- **D: GitHub → auto-generated ephemeral Contract** — chosen

**Core insight**: GitHub IS the system of record. Local Mission Contract is an **AI execution view** — auto-generated from Issue, enriched with project context (file paths, test commands), discarded after PR merge.

### vi-agent Patterns Borrowed vs Rejected

**Borrowed:**
- Mission lifecycle loop (claim → execute → deliver)
- `gh pr create` as delivery mechanism
- Merge count as throughput metric
- YAML config for team setup
- Skill freshness concept

**Rejected:**
- `board.md` as source of truth (GitHub IS the board)
- Port isolation (too project-specific)
- Forced worktree (Claude Code already supports it)
- Separate code-reviewer agent (folded into /team-ship)
- Slack/Telegram messaging (out of scope for v2.0)

### Quality Gate: Three-Layer Defense

```
Layer 1: .githooks/pre-commit  → lint (seconds)
Layer 2: .githooks/pre-push    → tests (minutes)
Layer 3: GitHub Actions CI     → full suite on PR
         + Branch Protection   → require CI + review
```

### Version Management: Three Levels

- Skill version: semver in config.yml + CHANGELOG
- Schema version: migration on config format changes
- Project milestones: GitHub Milestones for team versioning
