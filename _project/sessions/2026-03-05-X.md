## Key Bugs

### CRITICAL: `_branch_pattern()` `${p:-default}` with `{}` in default value

**Root cause**: Bash's `${var:-default}` closes at the first unmatched `}`. Bare `{issue}` braces inside the default don't count as nested expansions. So `echo "${p:-mission/{issue}-{slug}-{user}}"` is parsed as:
1. `${p:-mission/{issue}` — parameter expansion (closed at first `}`)
2. `-{slug}-{user}}` — leftover literal text concatenated to output

Even when `p` is non-empty, the leftover text appends. Result: `mission/99-test-e2e-test-e2e-liya}` instead of `mission/99-test-e2e`.

**Discovered via**: actual branch creation on vi_agent with `bash -x` tracing.

**Fix**: Replace `${p:-...}` with explicit `if [ -z "$p" ]; then p="default"; fi; echo "$p"`.

**Lesson**: Never use `${var:-default}` when the default contains `{}` characters. This is a general bash pitfall not documented in most guides.

### MEDIUM: `check-freshness` subshell `exit` bypasses `|| true`

**Root cause**: `cmd_read_field` uses `exit 3` (not `return 3`). When called inside `$(...)`, `exit` kills the subshell immediately — `|| true` inside the subshell never executes. Then `set -e` in the parent kills the whole script.

**Fix**: Pre-check file existence before calling `cmd_read_field`, and move `|| true` outside the subshell.

**Lesson**: `$(function_with_exit || true)` — the `|| true` is dead code when the function uses `exit` instead of `return`.

### LOW: protect-check USAGE comment

USAGE header said "Exit 1" but actual code exits 3. Fixed comment.

## Pattern: `exit` vs `return` in bash functions

Third major bash pitfall discovered across Sessions W-X:
1. Session W: `set -e` + `&&` chains (exit doesn't trigger)
2. Session W: `${p:-default}` with `{}` in default (premature close)
3. Session X: `$(func_with_exit || true)` (exit kills subshell, || true is dead)

All three are bash-specific behaviors that look correct on casual review. Only found via actual execution on production-like configs.
