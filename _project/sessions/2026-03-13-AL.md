## 🟠 Round 2: Git 模型对比 — teamwork vs Git Flow 图

> #### 💬 YaSong
>
> 我们的 git 模型设计和 https://res.cloudinary.com/about-gitlab-com/image/upload/v1749673714/Blog/Content%20Images/AdobeStock_569852816.jpg 还有多遥远,有何优缺点与不同?

#### 🔮 Claude

*（WebFetch 获取图片，识别为经典 Git Flow 模型：Main/Develop/Release/Release Fixes/Feature/Hot Fixes 6 条分支）*

逐层对比：

| 维度 | Git Flow | Teamwork |
|------|----------|----------|
| 永生分支 | 2 条（Main + Develop） | 1-2 条 |
| Feature 分支 | 手动命名 | `mission/{issue}-{slug}-{user}` 自动命名绑 Issue |
| 并行隔离 | 靠分支 | worktree 文件系统级隔离 |
| Release 流程 | Release + Release Fixes 双分支 | `/team-rc` 单分支 + cherry-pick |
| RC 迭代 | RC1→RC2→RC3 线性推进 | cancel + re-cut 重建式 |
| 合并方式 | merge commit | squash merge via PR |
| 自动化 | 纯人工 | AI 驱动全链路 |

**Teamwork 优势**：更简单拓扑、worktree 隔离、Issue-Branch-PR-Contract 四位一体、AI 可执行
**Teamwork 差距**：无显式 Develop 分支语义、RC 迭代不够丰富、无 Release Fixes、无多版本并行

**结论**：Git Flow 为大团队+长周期设计，Teamwork 为 AI+小团队+快速迭代设计。Trade-off 是对的。

- Tier 2（中等杠杆）：Phase Omega 在 team-issue 中、Gate 3 在 team-claim 中、Proactive Triggers 在 team-drive 中
