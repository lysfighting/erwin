Bundle-scoped `decision_id` values no longer become non-materializable once the latest scheduler snapshot has promoted them into `active-council`; runtime now falls back to the active meeting's persisted `source_decision_packet`, refreshes the live council from current scheduler context, and still reuses the existing meeting.

- extended core smoke to prove re-materializing an already-active bundle decision:

  - reports `reused_existing_meeting`
  - keeps `candidate_governor_packets`
  - keeps candidate-governor context on the refreshed meeting packet
