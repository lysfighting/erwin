# Session V — Teamwork v2.7.0 Script Extraction

**Date**: 2026-03-04
**Focus**: Extract deterministic operations from skill prose into reusable bash scripts

## Context

User invoked `/drive` with: "应该重新梳理整个teamwork工具的流程和实现,看看是否过度依赖 llm,应该尽可能将确定的动作和流程写成脚本,1 是稳定 2 是高效对吗?,要辩证得看,不要先入为主"

Translation: Review teamwork tools for LLM over-dependency. Deterministic operations should be scripts for (1) stability (2) efficiency. Look dialectically, don't be preconceived.

## Methodology

### Phase Ω: Dialectical Analysis

1. **Pantheon consultation** (.claude/pantheon/): Von Neumann (mechanism-content separation), Gödel/Turing (decidability boundaries), Shannon (signal vs noise), Dijkstra (constraint as clarity)
2. **Operations catalog**: 228 operations across 6 skill files — 145 DETERMINISTIC (64%), 48 LLM-JUDGMENT (21%), 35 MIXED (15%)
3. **Thesis** (user's position): More scripts = stability + efficiency. Evidence: v2.6.1 found 18/21 bugs in deterministic code; 2 existing scripts had 0 bugs.
4. **Antithesis**: Over-scripting adds interface complexity, reduces adaptability.
5. **Synthesis** (Von Neumann): Script universal mechanisms (cross-skill deterministic ops), keep specific content in .md files.
6. **Verdict**: AGREE + EXTEND

## What Was Built

### 6 Skill Files Refactored

- team-claim.md: branch creation → tw-git.sh, label transition → tw-label.sh
- team-drive.md: freshness → tw-contract.sh, protect → tw-git.sh, checkbox → tw-contract.sh
- team-ship.md: most changes — push, PR, labels, contract, rebase all → scripts
- team-release.md: merge, tag, commit → tw-git.sh
- team-issue.md: version bump only (mostly LLM judgment)
- team.md: freshness → tw-contract.sh, skill_version updated

## Design Principles

1. Scripts accept LLM-generated content as **parameters** (pure I/O boundary)
2. Scripts self-discover config via `SCRIPT_DIR` + `tw-config.sh`
3. Subcommand pattern: `tw-{domain}.sh {subcommand} [args...]`
4. macOS compatible, meaningful exit codes, stderr for errors
5. Skill .md files become pure orchestration + judgment

## Key Insight

Von Neumann's mechanism-content separation maps perfectly to the LLM skill architecture: **scripts = hardware (universal, deterministic)**, **skill.md = software (specific, adaptive)**. The v2.6.1 audit proved this — 18/21 bugs were in deterministic operations that LLM re-interpreted differently each time. Scripts lock the mechanism; LLM focuses on judgment.
