# Session Log — 2026-03-30 Q

## Summary

Closed a deeper governance gap by making explicit bundle governors and live bundle councils check each other instead of coexisting silently.

## What Changed

- Added runtime detection for bundles where:
  - an active `bundle_governor_established` signal exists
  - an active bundle-scoped meeting also exists
  - the explicit governor mission and the live bundle-council host mission do not match
- Those mismatches now surface as invalid governance in scheduler maintenance via `clear_invalid_bundle_governor`.
- Core smoke now proves:
  - a conflicting explicit governor can be emitted while a bundle council is live
  - scheduler escalates the mismatch into maintenance
  - the mismatch reason names both the explicit governor and the live council anchor
  - clearing the conflicting governor returns the bundle to a consistent control-plane state
- Smoke sequencing was also tightened so the later decision-hold scenario no longer inherits stale escalation backlog from the earlier bundle-conflict coverage.

## Validation

- `gofmt -w internal/harness/runtime.go`
- `go test ./...`
- `bash scripts/harness-smoke-test.sh`
- `bash scripts/harness-doctor.sh`
- `bash scripts/harness-adapter.sh validate`

## Result

`Harness` now treats “explicit leader adoption” and “live council governance” as interacting authority anchors rather than unrelated facts. When they disagree, the control plane escalates the mismatch into maintenance instead of silently carrying split governance.
