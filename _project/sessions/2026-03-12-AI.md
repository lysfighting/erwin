# Session AI — Teamwork v3.8.3: /team-rc cancel + upstream-first RC

**Date**: 2026-03-12
**Duration**: ~60 min (estimated, 00:46 commit)

## Mission

实现 `/team-rc cancel` 子命令和 upstream-first RC 模型。这是 Session R (2026-03-04) 中讨论的 RC 分支删除需求的落地实现。

## Background

Session R 的设计讨论确立了以下原则：
- RC 是冻结快照，不在 RC 上直接修 bug
- 分支删除需要安全确认
- Skill 管 git 操作，Action 管部署

本次实现将这些原则具体化为 upstream-first 模型。

## What Was Done

### `/team-rc cancel` — Cancel Flow (Steps C1-C5)

新增子命令，删除当前 RC 分支（local + remote）：

1. **C1**: 检测当前 RC 分支（`rc/*` pattern）
2. **C2**: 验证 RC 存在（local or remote）
3. **C3**: AskUserQuestion 确认删除
4. **C4**: 删除 local branch (`git branch -D`)
5. **C5**: 删除 remote branch (`git push origin --delete`)

### Upstream-first model

核心设计变更——RC 不可变（immutable）：

```
旧模型: 发现 bug → 在 RC 上修 → merge-back 到 develop
新模型: 发现 bug → 在 develop 上修 → /team-rc cancel → /team-rc (re-cut)
```

优势：
- 无需 merge-back（develop 始终是 superset）
- RC 作为 bus 比喻：错过这班就坐下一班
- 简化了 promote flow（不需要 cherry-pick reminder）

### Prepare Flow 增强

当 RC 已存在时，从 plain-text STOP 改为 AskUserQuestion 三选一：
- Promote（升级到 production）
- Cancel（删除当前 RC）
- Exit（退出）

### Promote Flow 修正

- 显式 branch deletion（local + remote）替代 `--delete-branch` flag
- 移除过时的 cherry-pick reminder

### Post-merge.yml — PR body checkbox

新增 Step 4：merge 后自动将 PR body 中的 `- [ ]` → `- [x]`。之前只处理 Issue body checkboxes。

### Docs 更新

- `team.md help`: 添加 `/team-rc cancel` 行
- `team.md learn`: RC lifecycle section 重写为 upstream-first model
- `docs/teamwork-ai-manual.md`: command table + Phase 2 verify + RC Freeze Rule + Only One RC section

## 设计决策

### 为什么 cancel 而不是 delete？

"Cancel" 暗示这是流程中的一个步骤（取消当前 RC 周期），而非单纯的分支删除操作。与 upstream-first 模型语义一致：cancel this RC → fix on develop → cut new RC。

### 为什么不在 RC 上修 bug？

1. 避免 merge-back 复杂性
2. Develop 始终包含所有变更（single source of truth）
3. RC 上的修改可能引入新问题，而 develop 上有完整 CI 保护
