# Session U — Teamwork v2.6.1 Falsification Audit

**Date**: 2026-03-04
**Focus**: Critical code review of entire teamwork skill set using Popper's falsification method

## Context

User invoked `/drive` with: "查询 pantheon 的指导思想,有没有告诉你不要先入为主,你要以批判的眼光检查一下代码"
Then: "同理，你应该重新梳理整个teamwork工具的流程和实现,看看是否还有bug,要辩证得看,不要先入为主"

## Methodology

Consulted `.claude/pantheon/` for anti-bias thinkers:
- **Karl Popper** — Falsificationism: try to DISPROVE, not confirm
- **Descartes** — Systematic doubt
- **Ibn al-Haytham** — Experimental verification
- **Francis Bacon** — Four Idols (mental biases)

Applied: assume bugs exist, trace actual execution, question every line.

## Audit Process

1. **Phase 1**: Applied Popper to post-merge Action → found 3 bugs (regex, type, race condition) → fixed + committed
2. **Phase 2**: Spawned 5 parallel audit agents to review all 7 files:
   - Agent 1: team.md (18 bugs found)
   - Agent 2: team-ship.md (19 bugs found)
   - Agent 3: team-claim.md (18 bugs found)
   - Agent 4: team-issue.md + team-drive.md (22 bugs found)
   - Agent 5: team-release.md + tw-config.sh (20 bugs found)
3. **Phase 3**: Synthesized ~80 findings → triaged → fixed 21 verified bugs across 7 files

## Key Findings

### CRITICAL (6 bugs — would cause real failures)
1. Freshness check broken in team.md + team-drive.md (ISSUE_TITLE/ISSUE_BODY never extracted from JSON)
2. PyYAML dependency in merge mode (not in Python stdlib)
3. Branch protection API sends JSON as string (gh api --field limitation)
4. CHANGELOG Python script vulnerable to shell injection
5. git merge uses stale local base branch without fetch
6. Version bump pushed to wrong branch in dual-branch mode

### HIGH (15 bugs — wrong behavior)
- `init` force mode promised but never implemented
- Hardcoded `status:` label prefix across 5 files (team.md, team-ship.md, team-claim.md, team-issue.md, setup-github-labels.sh)
- macOS sed `\+` syntax, MILESTONE_FLAG quoting, undefined ISSUE_TITLE
- Missing `--state` flags on `gh pr list`
- setup-github-labels.sh hardcoded `"mission"` label

## Method Lesson

Popper's falsificationism is the correct approach for self-review: **assume your code has bugs and try to prove it**. The naive approach (read code and "confirm it looks right") found 0 bugs in Session T. The falsification approach found 21 real bugs in the same code.

Bacon's Idol of the Tribe was the primary failure mode — we were biased toward "recently written code is correct" because we just wrote it.
