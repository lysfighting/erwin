### 2. Design Discussions

Three substantive discussions that informed v2.5.0:

**Version management Q&A** — Explained that teamwork uses GitHub Milestones (not labels) for version tracking. `versions.current` in config is the key; Milestone progress comes from GitHub API (`open_issues`/`closed_issues`). Milestone creation is still manual (vi_agent has none created).

**`/team-release` proposal review** — Evaluated the proposal against GitHub's actual patterns. Concluded: the milestone-close → git tag → gh release create --generate-notes pattern is the "product team" variant, not OSS library pattern. Correct approach. Key gap in proposal: version_file (bumping version in code). AI audit is valuable IF spec_path exists. Actions auto-deploy via `release: [published]` is standard and should be part of /team init template.

**`/team init` idempotency review** — Running `/team init` on a project with existing config (e.g., vi_agent's customized .teamspace/config.yml) destroys all customizations. Root cause: Step 4b writes unconditionally. Fix: section-level merge (preserve everything, update skill_version, append missing sections).

### 3. Teamwork v2.5.0

**New: `team-release.md`** — 11-step version release skill:
1. Pre-flight (versions.current required, REPO via gh)
2. Milestone check (show open/closed, warn if open issues remain)
3. AI audit (conditional on versions.spec_path — reads spec → compares Success Criteria vs merged PRs → ✅/⚠️/❌)
4. User confirmation
5. `git tag {VERSION}` + push
6. `gh release create {VERSION} --generate-notes`
7. Close GitHub Milestone
8. Prompt next version
9. Create next Milestone
10. Update config versions.current + commit
11. Summary

**Fixed: team.md Step 4b** — MERGE MODE when config exists:
- `sed` updates skill_version in-place
- Python3 detects missing top-level sections
- Appends only missing sections (project/conventions/label_prefix/quality)
- Preserves: team/members, github, worktree, versions, roles, any custom sections

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Tag format | Use `versions.current` as-is | Simplest, 0 config; team controls format via config value |
| Init merge granularity | Section-level | Preserves custom schemas (vi_agent's `github:` block) without YAML dump reformat |
| version_file (code version bump) | Deferred to v2.6 | Language-specific, adds complexity; core flow works without it |
| AI audit trigger | Conditional on spec_path | No spec → skip cleanly; no false positives |
