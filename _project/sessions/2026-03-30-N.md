# Session Log — 2026-03-30 N

## Summary

Bridged scheduler human-decision packets directly into durable council state. `Harness` can now materialize either the current primary scheduler decision or a specific stable `decision_id` into an active meeting, using the authoritative host run for the chosen mission and persisting the source decision packet plus scheduler snapshot linkage inside the meeting object itself.

## What Changed

- Added scheduler decision lookup from the latest durable scheduler snapshot.
- Added decision-aware host mission/run resolution for meeting materialization.
- Added `meetings materialize-primary-decision [--mission=MISSION_ID]`.
- Added `meetings materialize-decision DECISION_ID [--mission=MISSION_ID]`.
- Materialized meetings now persist:
  - `source_decision_id`
  - `source_decision_scope`
  - `source_decision_kind`
  - `source_decision_surface`
  - `source_decision_snapshot_id`
  - `source_decision_snapshot_ref`
  - `source_decision_packet`
- Meeting packets now retain scheduler snapshot refs and decision-context notes/recommended actions.
- Core smoke now proves both primary-decision materialization and decision-id materialization.

## Validation

- `gofmt -w internal/harness/runtime.go`

## Result

`Harness` no longer leaves scheduler human-decision packets as read-only portfolio output. Leader-facing runtime can now cross the boundary into a governed council with durable provenance, which narrows one of the remaining deep gaps between scheduler/control-plane state and automated council execution.
