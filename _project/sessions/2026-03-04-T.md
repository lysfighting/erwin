## Design Decisions

- **Config key naming**: `conventions.release_branch` (not `deploy.release_branch`) — it's a git convention, not a deploy concern
- **Default behavior**: `release_branch` defaults to `base_branch` value → single-branch mode = v2.5 behavior, zero migration needed
- **deploy section is optional**: Not in merge mode required sections list. Projects opt-in by adding `deploy.staging_workflow`
- **"erwin v2 format" references kept**: In team.md schema documentation, these explain config format variants generically, not project coupling. Changed `vi_agent` comment to "nested schema".
