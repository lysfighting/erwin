# ADR-0009: Teamwork Skill — Multi-Person Coordination via Markdown + Claude Code

- **Date**: 2026-03-02
- **Status**: Accepted

## Context

The team needs a structured system for parallel AI-assisted development. Requirements:
- 3-5 developers working on the same repo simultaneously
- Each person uses Claude Code locally with assigned missions
- Task coordination through the repo itself (no external tools)
- Integration with existing /drive methodology
- Must work tomorrow (MVP mindset)

Key challenge: metadata merge conflicts when multiple people update shared status files.

## Decision

### 1. Per-Person Status Files (Zero-Conflict Architecture)

Instead of one global kanban board, each person gets their own status file (`_teamwork/members/{username}.md`). Only the file owner edits it. Global board view is dynamically generated by reading all member files.

**Rejected alternative**: Single BOARD.md — guaranteed merge conflicts with 5 concurrent editors.
**Rejected alternative**: Sectioned BOARD.md — reduces but doesn't eliminate conflicts.

### 2. Four Skills (One Suite)

| Skill | Purpose |
|-------|---------|
| `/teamwork` | Init system + dashboard |
| `/team-get-mission` | Claim mission, create branch |
| `/team-drive` | Execute (wraps /drive) |
| `/team-complete` | Push, rebase, merge, close |

Packaged as one directory (`skills/teamwork/`) with multiple .md files. install.sh updated to support multi-file skill directories.

### 3. Identity via `gh auth status`

Zero-configuration identity detection. Each person's GitHub username maps to their role in `config.md`.

**Rejected**: Environment variables (requires manual setup per machine).
**Rejected**: AskUserQuestion every time (friction).

### 4. Wrap /drive, Don't Clone It

`/team-drive` sets teamwork context (mission contract, status tracking) then enters drive execution mode. Includes core drive principles (Dual Wheel, Swarm-First) but skips inapplicable phases (Phase T team assembly — user IS the team member).

### 5. erwin-init Integration: Philosophy, Not Code

Borrowed from erwin-init:
- Zero-question setup (auto-detect everything)
- Living status file pattern (CURRENT.md → members/{name}.md)
- Git conventions (extended for team branches)

Not borrowed: GOALS.md, ADRs, Idea Garden, MEMORY.md (not relevant to daily task execution).

### 6. No erwin- Prefix

Per ADR-0008 naming convention: Teamwork is an independent tool, not framework core. So: `/teamwork`, not `/erwin-teamwork`.

## Consequences

**Positive**:
- Zero metadata merge conflicts (per-person files)
- Zero configuration (gh auth detection)
- Integrates with existing /drive methodology
- Pure Markdown + Git — no external dependencies
- Resumable (member file IS the save state)

**Negative**:
- install.sh needed update for multi-file skills
- Dashboard requires reading N files (O(N) with team size, acceptable for 3-5 people)
- No real-time notifications (git-based, not event-driven)
- Linear merge can bottleneck when many people finish simultaneously
