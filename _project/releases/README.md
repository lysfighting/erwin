# Releases

Narrative release notes (more detail than CHANGELOG.md).

## When to Write

Create a release note file for every MINOR or MAJOR version bump.
PATCH versions can just live in CHANGELOG.md.

## Naming Convention

`vX.Y.Z.md`

## Template

```markdown
# Release vX.Y.Z

- **Date**: YYYY-MM-DD
- **Session**: [link](../sessions/YYYY-MM-DD.md)
- **Issues Closed**: ISS-NNNN, ISS-NNNN

## What Shipped

[Narrative. Not just bullet points — tell the story of what changed and why.]

## Key Decisions Made

[Reference ADRs: see ADR-NNNN for the decision to use X over Y]

## What We Learned

[Surprises, obstacles, insights for future reference]

## What's Next

[Preview of the next version]
```
